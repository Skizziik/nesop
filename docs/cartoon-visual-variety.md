# ТЗ: визуальное разнообразие мультиков

Oct 11, 2026 · @Максим

## Цель и критерии успеха

Цель: 100 эпизодов подряд выглядят по-разному, а герои узнаются с первого кадра. Это нужно и детям (новое интересно), и YouTube: он демонетизирует шаблонный однотипный контент на уровне всего канала.

Ограничения текущего стека:

- Векторная перекладка на Remotion (React + SVG), модуль `packages/templates/src/cartoon/`.
- Сценарий и режиссура в `services/api/app/pipeline/cartoon.py`: план, истории, редактор, Director.
- Видеокарта 8 ГБ, всё рендерится локально; эпизод 20-25 минут, это 36-45 тысяч кадров при 30 fps.
- Полная детерминированность: один и тот же документ эпизода всегда рендерится одинаково.
- Аудитория 2-5 лет: безопасность и мягкость важнее зрелищности.

| Критерий успеха | Порог |
| --- | --- |
| Разных визуальных сетапов (локация + состояние мира + оформление) в эпизоде | от 6 |
| Разных предметов в кадре за эпизод | от 12 |
| Похожесть с любым из последних 10 эпизодов (индекс Жаккара по отпечатку, раздел 10) | до 0.35 |
| Доля экранного времени самого частого сетапа | до 30% |
| Время без смены плана камеры | до 8 с |
| Одно и то же действие героя подряд | до 2 раз |
| Тест «10 кадров»: человек видит, что 10 кадров из 10 случайных эпизодов из разных серий | 9 из 10 |
| Ошибки сборки по автопроверке (раздел 12) | 0 |

## Главный принцип: постоянное ядро, переменный мир

Меняется мир вокруг героев, а не сами герои. Так устроены Peppa Pig и Bluey: дизайн персонажей не меняется годами, а каждая серия выглядит иначе за счёт места, погоды, предметов, гостей и ситуации.

Не меняется никогда (ядро сериала):

- Форма, пропорции, цвета и голоса 5 основных героев.
- Базовая планировка домашних локаций: дом Бенни всегда тот же дом.
- Стиль рисовки: толщина линий, цветной контур, палитра (раздел 11).
- Структура эпизода: интро, истории, песенки, прощание.

Меняется в каждом эпизоде:

- Где и в каком состоянии мир: время суток, погода, сезон, оформление.
- Что в руках и вокруг: предметы.
- Во что одеты: костюмы поверх базового дизайна.
- Кто в гостях: второстепенные герои.
- Как снято: планы, движения камеры, переходы.
- Что происходит помимо реплик: эффекты, звуки, взаимодействия.

Правило для разработки: любая новая вариативность добавляется как данные в каталог, а не как if-ветки в коде сцен. LLM выбирает только из каталога, код только исполняет и проверяет.

## Архитектура

Одна точка правды: каталог ассетов в TypeScript, из которого при сборке генерируется JSON для Python. Сейчас списки локаций и героев продублированы в `cartoon.py` и в TS; при росте до сотен ассетов это начнёт ломаться.

**Единый каталог.**

- Папка `packages/templates/src/cartoon/catalog/`: реестры по типам (locations, props, outfits, fx, dressings, guests, actions, emotions, shots, transitions, sfx).
- Каждая запись: `id`, `label` (по-русски, для дашборда), `llm` (одна строка по-английски для промпта), `tags`, совместимость (локации, сезоны, погода, время суток), `states` для предметов, `cost` (тяжесть рендера 1-3).
- Скрипт `catalog:export` пишет `services/api/app/pipeline/cartoon_catalog.json`; тест падает, если JSON устарел.
- `cartoon.py` строит enum в JSON-схемах LLM и текст библии сериала из этого JSON, а не из констант в коде.

**Палитры вместо жёстких цветов.**

- Все локации рисуются через токены (`pal.sky1`, `pal.grass`, `pal.wall`, `pal.wood`…), без hex прямо в JSX.
- `resolvePalette(location, world)` = база локации × модификаторы времени суток, погоды и сезона.
- Тогда осень, вечер и дождь достаются почти бесплатно для любой локации, включая будущие.

**Детерминированная случайность.**

- У сцены есть `seed` (хэш id проекта + номер сцены); весь процедурный выбор через `random(seed + ключ)` из Remotion, `Math.random` запрещён.
- По сиду выбираются мелочи: какие цветы, где облака, что на полке, какая картина на стене, цвет игрушек на полу. Каркас локации при этом не меняется.

**Точки в локациях.**

- Каждая локация объявляет `spots` (куда герой может дойти: `swing`, `slide_top`, `sofa`, `table`, `door`, `tree`) и `surfaces` (куда ставят предмет: `table_top`, `shelf`, `sand`, `ground`).
- Позиции left/center/right остаются, но сценарий может написать «Benny goes to the swing».
- У точек есть поза по умолчанию: `sofa` → sit, `swing` → swing, `slide_top` → slide.

**Новый конвейер эпизода.**

1. План эпизода (LLM): истории, темы, ключевые слова; получает историю показа и квоты.
2. Сценарий истории (LLM): биты, теперь с предметами, точками и гостями.
3. Редактор детского ТВ (LLM): как сейчас, плюс безопасность предметов.
4. Арт-директор (LLM, новый шаг): визуальный план каждой сцены (раздел 10).
5. Валидатор (код): всё из каталога, всё совместимо, квоты соблюдены; иначе точечная перегенерация.
6. Режиссёр (код): тайминги, позиции, камера, авто-эффекты, авто-звуки, переходы.
7. Автопроверка (код + контактный лист кадров, раздел 12).
8. Рендер и YouTube-пакет.

## Модель данных

SceneDoc расширяется пятью полями (seed, world, props, fx, sfx) и переходом; старые документы без этих полей рендерятся как сейчас (день, ясно, лето, seed 0).

```ts
type TimeOfDay = "morning" | "day" | "evening" | "night";
type Weather = "clear" | "cloudy" | "rain" | "snow" | "windy";
type Season = "spring" | "summer" | "autumn" | "winter";

interface WorldState {
  time: TimeOfDay;
  weather: Weather;
  season: Season;
  dressing?: string; // id оформления из каталога: "birthday", "picnic"...
}

type PropAt =
  | { kind: "ground"; x: number }
  | { kind: "spot"; spot: string } // точка или поверхность локации
  | { kind: "hand"; char: string; hand: "L" | "R" | "both" };

interface PropKey {
  t: number;
  at?: PropAt;
  state?: string; // "whole" | "bitten" | "popped"...
  anim?: "bounce" | "spin" | "fall" | "throw" | "float_away";
}

interface PropInstance {
  uid: string;   // "ball1"
  prop: string;  // id из каталога: "ball"
  color?: string; // вариант цвета из палитры предмета
  keys: PropKey[];
}

interface FxEvent { t: number; fx: string; char?: string; x?: number; y?: number; dur?: number }
interface SfxEvent { t: number; sfx: string; volume?: number }

interface SceneDoc {
  // существующие: location, kind, start, duration, camera, actors, lines, overlays
  seed: number;
  world: WorldState;
  props?: PropInstance[];
  fx?: FxEvent[];
  sfx?: SfxEvent[];
  transitionIn?: "cut" | "fade" | "iris" | "wipe" | "star" | "bubble";
  imagination?: string; // id воображаемого мира, если сцена «понарошку»
}

interface ActorDoc {
  id: string;       // основной герой или гость из каталога
  outfit?: string[]; // слои: ["raincoat", "boots"]
  keys: ActorKey[];  // в ActorKey добавить spot?: string
}
```

В схему бита сценариста (`BEAT` в `cartoon.py`) добавить: `props` (какие предметы участвуют и что с ними: give, throw, eat…), `spot` вместо или вместе с `move.to`, `guest` (выход гостя). Выход арт-директора на историю:

```json
{
  "season": "autumn",
  "scenes": [
    {
      "scene_index": 0,
      "world": { "time": "day", "weather": "rain" },
      "dressing": null,
      "outfits": { "benny": ["raincoat", "boots"], "mia": ["rain_hat"] },
      "props": [{ "uid": "umb1", "prop": "umbrella", "start": { "hand": "mia" } }],
      "set_pieces": ["puddle_jump"],
      "fx_cues": [{ "beat": 3, "fx": "splash" }],
      "special_shots": [{ "beat": 5, "shot": "insert", "target": "umb1" }],
      "transition_in": "wipe"
    }
  ]
}
```

## Предметы и взаимодействия

Предметы дают больше всего разнообразия на единицу работы: сюжет детской серии почти всегда крутится вокруг предмета. Цель v1: 60 предметов в 6 группах.

| Группа | Примеры id | Штук |
| --- | --- | --- |
| Игрушки | ball, kite, teddy, blocks, toy\_car, balloon, bucket\_spade, jump\_rope, drum, puzzle, yo\_yo, boat | 12 |
| Еда (полезная по умолчанию) | apple, banana, carrot, cookie, sandwich, cake, ice\_cream, juice, watermelon, pizza\_slice, strawberry, milk | 12 |
| Быт и гигиена | toothbrush, soap, towel, cup, plate, spoon, book, pillow, blanket, night\_lamp | 10 |
| Природа | flower, leaf, shell, stone, acorn, snowball, stick, butterfly\_net, seed\_packet, watering\_can | 10 |
| Одежда как предмет | umbrella, hat, scarf, mittens, boots, backpack | 6 |
| Праздник и творчество | gift, crayons, drawing, paint\_brush, star\_wand, party\_hat, music\_box, toy\_camera, map, magnifier | 10 |

Каждый предмет в каталоге:

- SVG-компонент по стиль-гайду, размер в единицах мира, точка хвата для руки;
- состояния, например: balloon {full, popped, flying}, cake {whole, sliced, eaten}, apple {whole, bitten}, ice\_cream {full, melting, empty}, kite {held, flying}, cup {empty, full, spilled}, gift {wrapped, open}, book {closed, open};
- 2-4 варианта цвета из утверждённой палитры;
- теги и совместимость (snowball только зимой, kite только снаружи и не в дождь);
- флаг `adult_only` для предметов, которые в руках ребёнка опасны (кастрюля, плита, ножницы): их держат только взрослые герои.

Взаимодействия:

- Новые действия: hold, pick\_up, put\_down, give (передача из руки в руку с синхронизацией двух героев), throw и catch, eat (откусывание меняет состояние), hide\_behind, show\_to\_viewer (поднять предмет к камере), look\_for (предмет спрятан за объектом в точке локации).
- Rig экспортирует координаты кистей: функция `handPositions(spec, pose)` вместо расчёта внутри `Arm`. Предмет рисуется в точке руки, над или под рукой по флагу.
- Траектории: бросок по параболе, падение с отскоком, шарик улетает вверх с покачиванием, мяч катится с вращением.
- Режиссёр сам ставит крупный план (insert) на предмет при его первом появлении в истории.

## Мир: время, погода, сезон, события

Состояние мира задаётся на сцену и меняет палитру, частицы и мелкие детали: одна площадка становится пятью разными местами.

**Время суток.** Утро (розово-жёлтое небо, длинные тени), день, вечер (тёплый оранжевый), ночь (синие тона, светящиеся окна, луна, звёзды, фонари на улице).

**Погода.**

- Облачно: больше облаков, без солнца, палитра на 10-15% темнее и холоднее.
- Дождь: детерминированные капли (до 250 частиц), лужи, брызги из-под ног (авто-эффект), мокрые блики.
- Снег: снежинки (до 200), снежные шапки на деревьях, крышах и заборе (отдельный слой каждой локации), белая земля, следы.
- Ветер: сильнее качаются деревья, уши и хвосты, летят листья, облака быстрее.
- В помещениях погода видна в окне, а свет в комнате подстраивается под время суток.

**Сезоны.** Весна (цветы, почки), лето, осень (оранжевые кроны, листья на земле, тыквы), зима (голые деревья и ели, снег). Таблица совместимости в каталоге: снег не на пляже, ночь не на пляже в v1, листопад только осенью.

**Оформления (10).** Накладываются на любую подходящую локацию: birthday (шарики, флажки, торт, колпаки), picnic (плед, корзина), tea\_party (игрушки за столом), camping (палатка, фонарик), harvest (тыквы, корзины яблок), winter\_holiday (огоньки, подарки, снеговик, без религиозных символов), blanket\_fort (крепость из одеял в дождь), art\_day (мольберт, рисунки на стене), music\_day (инструменты), garden\_party (гирлянды в саду).

**Новые локации (10).** farm, shop, kindergarten, doctor\_office (мягкий и совсем не страшный), pond, zoo, train (вагон, за окном бесконечный параллакс), park, grandma\_house, library. Каждая сразу делается на токенах палитры, со `spots`, `surfaces` и снежным слоем.

**Воображаемые миры (4), как игра «понарошку» в Bluey.** space (ракета из коробки, планеты), underwater (рыбки, пузыри), dino\_land (добрые динозавры), fairy\_castle. Вход через переход star или bubble, герои в костюмах, своя яркая палитра, но тот же стиль рисовки. Не больше одной такой сцены на историю, обязательно возврат в реальность.

## Персонажи: костюмы, действия, гости

Герои меняют одежду и умеют больше, но их силуэт, цвета и голоса неприкосновенны.

**Костюмы (20 слоёв по слотам).** Надеваются поверх базового наряда:

- head: party\_hat, rain\_hat, winter\_hat, sun\_hat, crown, chef\_hat, astronaut\_helmet (прозрачный);
- body: raincoat, pajamas, swimsuit, winter\_coat, superhero\_cape, kid\_apron, scarf;
- feet: boots, flippers;
- face: sunglasses, snorkel\_mask;
- hand: mittens, gloves\_garden.

Правила: костюм не закрывает лицо и не меняет форму головы и ушей. Авто-подбор режиссёром, если арт-директор не указал иное: снег → winter\_hat + scarf; дождь снаружи → raincoat + boots; пляж → sun\_hat или swimsuit; спальня ночью → pajamas; birthday → party\_hat.

**Боковой профиль при ходьбе (высокий приоритет).** Отдельная отрисовка головы и тела сбоку, разворот через 3/4 за 4-6 кадров. Без этого ходьба выглядит как двигающаяся картинка.

**Новые действия (около 20).** sleep, eat, drink, give, throw, catch, pick\_up, put\_down, slide, swing, splash (прыжок в лужу), hide, peek, tiptoe, spin, fall\_soft (смешно сесть на попу, безопасно), yawn, nod, shake\_head, cover\_eyes (прятки), high\_five. Парные действия (give, high\_five, hug) режиссёр синхронизирует: герои подходят друг к другу, руки встречаются в одной точке.

**Новые эмоции (3).** proud, shy, excited.

**Постоянные гости (6).** Фиксированный дизайн и свой голос в `VOICES`, записаны в каталоге навсегда: Grandpa Bear (дедушка Олли), Granny Bunny, Teacher Owl (воспитательница в садике), Doctor Elephant, Shopkeeper Fox, Farmer Goat. Для этого rig получает виды owl, elephant, fox, goat.

**Массовка.** Одноразовые фоновые жители (утки у пруда, дети на площадке, звери в зоопарке) из шаблонов видов с перекраской по сиду. Не говорят, живут на дальних слоях, только idle-анимации.

Запрет: никаких дизайнов, похожих на известных персонажей (свинка в платье, голубая собака и т.п.). Это и юридический риск, и риск пометки «чужой контент» на YouTube.

## Эффекты, звуки, камера

Эти три вещи делают из «двигающихся картинок» мультик; большую часть режиссёр ставит сам по правилам, без участия LLM.

**Визуальные эффекты (20).** sparkle, hearts, stars\_burst, zzz, sweat\_drop, idea\_bulb, question\_marks, exclamation, music\_notes, dust\_puff, speed\_lines, splash, confetti, steam, bubbles, leaf\_swirl, rainbow, magic\_trail, blush, ripple.

Авто-триггеры: приземление после jump → dust\_puff; run → speed\_lines; surprised → exclamation; cheer → stars\_burst; hug → hearts; sleepy → zzz; think, сменившийся на happy → idea\_bulb; шаг в луже → splash; песня → music\_notes. Арт-директор может добавить эффект явно (`fx_cues`).

**Звук.** Сейчас в мультике нет звуковых эффектов, только голоса и музыка, и это сразу выдаёт ненастоящий мультик.

- Библиотека 60+ коротких звуков: шаги по траве, полу, снегу и лужам, boing на прыжок, pop шарика, хлопки, whoosh на переходах, «динь» на искорки, откусывание, плеск.
- Эмбиент по локации и погоде: птицы в саду, волны на пляже, сверчки ночью, дождь, ветер.
- Источник: процедурная генерация (как `music.py`) или библиотеки с лицензией CC0 (Kenney, Freesound CC0); лицензия каждого файла фиксируется в каталоге.
- Авто-подстановка по действиям, эффектам и погоде; громкость под голосами с приглушением (ducking).

**Камера: планы (8).** establishing (общий при входе в новую локацию, 2-3 с), wide, medium, close, extreme\_close (реакция, до 1.5 с), two\_shot, insert (крупно предмет), over\_shoulder.

**Камера: движения (7).** static, follow\_pan (за бегущим), push\_in (момент осознания), pull\_out (раскрытие сюрприза), tilt\_up (шарик улетает), shake (лёгкая, при падении), whip\_pan (быстрый перевод внутри сцены).

Правила режиссёра:

- новая локация начинается с establishing;
- после шутки или сюрприза идёт крупный план реакции слушателя;
- первое появление предмета даёт insert;
- вопрос зрителю снимается крупно, герой смотрит в камеру;
- не дольше 8 с без смены плана и не больше 2 одинаковых планов подряд;
- доли на эпизод: wide 25-35%, medium 35-45%, close и insert 25-35%.

**Переходы (6).** cut, fade, iris (круг на герое), wipe, star (вход в воображаемый мир), bubble. Выбирает код: то же место в другое время → fade; новая локация → wipe; конец истории → iris; воображение → star.

## Арт-директор и контроль повторов

Сценарист отвечает за смысл, арт-директор за картинку, а код следит, чтобы эпизоды не повторяли друг друга.

**Арт-директор (новый LLM-шаг после редактора).**

- Вход: сценарий истории, каталог с совместимостью, история показа, квоты эпизода.
- Выход: визуальный план по сценам (схема в разделе «Модель данных»). Реплики он не трогает.
- Мир помогает истории: грустный момент → облачно, финал → солнце или радуга. Погода меняется только между сценами и с причиной в сюжете.
- Сезон выбирается на историю; в одном эпизоде истории могут быть в разных сезонах.

**Отпечаток эпизода.** Множество меток: сетапы `location:time:weather:season:dressing`, предметы, костюмы, гости, воображаемые миры, тема, главный герой каждой истории. Хранится в `meta.visual_fingerprint` проекта.

**Анти-повтор.**

1. До плана: в промпты плана и арт-директора передаётся список «недавно было» (самые частые метки последних 10 эпизодов) с просьбой этого избегать.
2. После арт-плана: код считает индекс Жаккара с каждым из последних 10 отпечатков.
3. Больше 0.35 → перегенерация арт-плана с явным списком «замени это», до 2 попыток; затем берётся лучший вариант.

**Квоты эпизода (проверяет валидатор).** От 3 локаций; от 2 разных состояний мира; хотя бы 1 особый момент (оформление, воображаемый мир или гость); от 12 предметов; главный предмет истории не повторяется 2 эпизода подряд; главные герои историй в эпизоде разные.

**Кулдаун ассетов.** У каждого ассета вес, который падает после использования и восстанавливается за 5-8 эпизодов. Арт-директору передаются свежие ассеты первыми, так всплывают и редко используемые.

**Обложки.** В отпечаток добавляются локация и доминирующий цвет каждой обложки. Обложки эпизода между собой и с последними 10 эпизодами не повторяют пару «локация + доминирующий цвет».

## Стиль-гайд и производство ассетов

Разнообразие не должно разрушить единый стиль: каждый новый ассет проходит стиль-гайд, линт и визуальную проверку на листе.

**Стиль-гайд** (`cartoon/STYLE.md` + константы в коде):

- Контур: цвет детали, затемнённый `shade(color, 0.3-0.35)`; чистый чёрный запрещён, тёмный INK `#2A1B33` только для глаз и рта.
- Толщина линии: 3-6 единиц мира у предметов и мебели, 4-5 у героев; на дальних слоях тоньше пропорционально глубине.
- Формы скруглённые: острые углы меньше 30° запрещены, у прямоугольников `rx` от 6.
- Блик: одна полупрозрачная светлая капля сверху слева (opacity 0.15-0.2).
- Палитра: утверждённый набор из \~40 цветов (сочные, светлые, без кислотных); предметы и костюмы берут цвета только из неё.
- Масштаб: таблица размеров относительно роста героя-ребёнка (\~300 единиц): мяч 50, стул 140, дверь 360 и так далее.
- Сложность: предмет до 25 SVG-элементов, локация до 400 элементов на кадр без частиц.

**Как добавляется ассет.**

1. Запись в каталоге + SVG-компонент по стиль-гайду.
2. Композиция `AssetSheet` автоматически рендерит лист: ассет во всех состояниях, цветах, временах суток и рядом с героем для масштаба.
3. Линт стиля (скрипт): нет `#000`, нет `Math.random`, все объявленные состояния рисуются, размер в допуске, цвета из палитры.
4. Визуальная проверка листа: Claude смотрит PNG, как сейчас с локациями, и правит до чистого результата.
5. Страница «Каталог» во вкладке «Мультики»: сетка всех ассетов с превью, фильтры по типу и тегам, где и как часто использовались.

**Нейросети.** SDXL-фоны или векторизация растра (vtracer) только как эксперимент на этапе 6, если векторная библиотека упрётся в потолок. Риски: другой стиль рядом с векторными героями и более медленная генерация.

## Автопроверки и производительность

Каждый эпизод проверяется кодом и по контактному листу кадров до рендера, а добавление погоды и частиц не должно замедлить рендер больше чем на 30%.

**Проверки кодом (после режиссёра).**

- Предмет в руке привязан к герою, который в этот момент есть в сцене.
- Говорящий герой в кадре и не перекрыт карточкой слова или субтитром.
- Герои не стоят друг в друге (дистанция от 180 единиц) и не уходят за край кадра во время реплики.
- Совместимость мира: снег не на пляже, сезонные предметы в своём сезоне, костюм подходит погоде.
- Квоты и похожесть (раздел про арт-директора).
- Безопасность: `adult_only` предметы только у взрослых.

**Визуальная проверка.** Контактный лист: 1 кадр каждые 15 секунд (около 100 кадров на эпизод, масштаб 0.3). LLM с поддержкой картинок ищет обрезанные лица, пустые кадры, висящие в воздухе предметы, нечитаемые карточки. Отчёт в `meta.qa`, ошибки видны на странице эпизода в дашборде.

**Производительность.**

- Сначала замерить текущую скорость рендера (кадров в секунду) на демо-эпизоде как базу.
- Частицы до 250 на кадр; без SVG-фильтров blur и drop-shadow в сценах (медленно в Chromium), свечение делать полупрозрачными фигурами.
- Статичные слои (дальний фон) мемоизировать по ключу `location + world + seed`.
- Если ещё нет: рендер эпизода частями по сценам с последующей склейкой, чтобы сбой не терял весь прогресс.

## Этапы и приёмка

7 этапов строго по очереди; Claude Code получает по одному этапу, после каждого рендерит демо-ролик в «Загрузки» и показывает контактный лист.

0. **Фундамент.** Единый каталог и экспорт в Python, токены палитры во всех 8 локациях, `seed` в сцене, `handPositions` из rig, композиция `AssetSheet`, страница «Каталог».
   - Приёмка: демо-эпизод выглядит как раньше; `cartoon.py` берёт все enum из JSON каталога; скорость рендера замерена как база.
1. **Мир.** Время суток, погода и сезоны для 8 локаций, погода в окнах помещений, таблица совместимости.
   - Приёмка: лист «8 локаций × все совместимые состояния» без артефактов; рендер медленнее базы не больше чем на 30%.
2. **Предметы.** 60 предметов с состояниями и хватом, действия hold, give, throw, catch, eat, pick\_up, put\_down, авто-insert.
   - Приёмка: сцена «Benny gives Mia an apple, Mia bites it, then throws a ball to Dot» собирается из сценария без ручных правок.
3. **Жизнь кадра.** Боковой профиль при ходьбе, костюмы со слотами и авто-подбором, +20 действий, +3 эмоции, эффекты с авто-триггерами, звуки и эмбиент.
   - Приёмка: 5-минутный эпизод, где каждые 8 секунд что-то меняется, звуки на всех прыжках и шагах.
4. **Режиссура и арт-директор.** Шаг арт-директора, валидатор, квоты, отпечаток и анти-повтор, планы, движения, переходы, автопроверки и QA-лист.
   - Приёмка: 3 эпизода подряд на одну тему, похожесть между любыми двумя до 0.35, выполнены все критерии из первого раздела.
5. **Расширение мира.** 10 новых локаций, 4 воображаемых мира, 10 оформлений, 6 постоянных гостей с голосами, массовка.
   - Приёмка: 10 эпизодов подряд проходят тест «10 кадров».
6. **Эксперимент (по решению).** Нейросетевые фоны или векторизация.
   - Приёмка: сравнение на 2 эпизодах, решение принимает Максим.

## Решения по умолчанию и открытые вопросы

Там, где ты пока не определился, решение принято по умолчанию; Claude Code работает по нему, пока ты не скажешь иначе.

| Вопрос | Решение по умолчанию |
| --- | --- |
| Нейросети для фонов | нет, только вектор; эксперимент на этапе 6 |
| Сезон | выбирается на историю, в эпизоде могут быть разные |
| Праздники | только светские: день рождения, пикник, сезонные; без религиозной символики |
| Гости | 6 постоянных с голосами + немая массовка |
| Воображаемые миры | да, не больше одной сцены на историю |
| Субтитры | оставить: полезно родителям и детям, которые учат английский |
| Имена и виды гостей | как в разделе про персонажей, можно поменять до этапа 5 |
| Порядок работ | этапы 0-6 по очереди, демо после каждого |

Открытые вопросы:

- Привязывать сезон серий к реальной дате публикации (осенние серии выходят осенью)? По умолчанию да, если дата публикации известна при создании.
- Песни с настоящим вокалом (ACE-Step) в это ТЗ не входят; нужно отдельное ТЗ.
