## 0. Инструкции для агента (Claude Code)

Ты строишь production-ready локальную «ферму» вертикальных роликов для YouTube-канала **@ItalianoPerTe** (обучение итальянскому, ~34k подписчиков, ~1.8k шортсов). Владелец хочет: открыть дашборд, выбрать серию, нажать одну кнопку и получить пачку готовых, разных, качественных шортсов.

Правила работы:
1. Сначала прочитай весь документ, затем создай `PLAN.md` с разбивкой на этапы из раздела 12 и чек-листом. Обновляй его по ходу.
2. Перед стартом задай владельцу **максимум 3 вопроса**, только если без ответа нельзя продолжать (например: есть ли NVIDIA GPU и сколько VRAM). На всё остальное принимай разумные решения сам и фиксируй их в `DECISIONS.md`.
3. Делай по этапам. Каждый этап заканчивается рабочим `docker compose up` и зелёными тестами. Не переходи к следующему этапу, пока текущий не работает end-to-end.
4. Всё, что касается внешних моделей и библиотек (версии, способ установки, лицензии), **проверяй по актуальной документации/Hugging Face в момент реализации**, а не по памяти. Экосистема TTS меняется каждый месяц.
5. Никаких заглушек типа `TODO: implement`. Если фича вынесена в «позже», она скрыта за feature-flag, но схема БД и интерфейсы под неё уже есть.
6. UI дашборда на **русском**. Контент роликов на **итальянском** (подписи вторым языком: английский, опционально русский/украинский/испанский, настраивается per-series).
7. Владелец работает на Windows с Docker Desktop. Всё должно подниматься на Windows (WSL2 backend), Mac и Linux. GPU опционален: CPU-профиль обязан работать полностью.

## 1. Что было на канале (референс формата)

Старые шортсы канала (сортировка «Старые» во вкладке Shorts): «Numeri a una cifra 0-9», «Articoli in italiano», «Numeri a due cifre 10-19», «Studiare», «Avere presente», «Impara l'italiano ancora più velocemente!» (напитки EN→IT).

Формат одной карточки (12-16 сек, 1080x1920):
- однотонный пастельный/насыщенный фон, меняется от ролика к ролику;
- сверху жёлтая плашка-заголовок (`Numeri a una cifra`);
- столбик пар: слева плашка (бордовая для цифр, чёрная для местоимений/английских слов/артиклей), справа белая плашка с итальянским словом КАПСОМ;
- голос читает строки по очереди, текущая строка подсвечивается: правая плашка зелёная, текст левой жёлтый;
- **последняя строка спрятана** (`???` справа, или `??` слева в формате артиклей): зритель пишет ответ в комментах. Это главный механизм вовлечения, его надо сохранить и развить;
- наклейка-закладка «сохрани» (красная лента с плюсом), иногда милые наклейки (котик, цветок);
- AI-ведущая (девушка) в правом нижнем углу, стоит и говорит.

Известный баг старых роликов: в «10-19» опечатка `DICIASSSETTE`. Отсюда требование: автоматическая проверка орфографии (раздел 6).

## 2. Цели и не-цели

**Цели**
- One-click: «Серия X, 10 штук» → через N минут 10 разных готовых mp4 + метаданные.
- Много форматов (раздел 4), сгруппированных в серии = будущие плейлисты.
- Встроенные механики хуков и комментов (раздел 5), а не «просто список слов».
- Выбор и скачивание TTS-моделей прямо из дашборда, прослушка, A/B сравнение голосов.
- Генерация идей через LLM с обязательной проверкой корректности итальянского.
- Живое превью ролика в браузере до рендера.
- Всё в Docker, данные и модели в volumes, переживают пересборку.

**Не-цели сейчас (но заложить архитектурно)**
- Автозагрузка на YouTube (этап 7, под feature-flag, по умолчанию выключена).
- Импорт аналитики YouTube и обучение генератора на том, что зашло (этап 8).
- Lip-sync аватар на GPU (этап 6, опционально).

## 3. Архитектура

### Сервисы (`docker-compose.yml`)

| Сервис | Стек | Роль |
|---|---|---|
| `web` | Next.js (App Router, TypeScript) + Tailwind + shadcn/ui + `@remotion/player` | Дашборд, живое превью роликов |
| `api` | Python 3.12, FastAPI, SQLAlchemy 2, Alembic, Pydantic v2 | REST API, бизнес-логика, LLM, оркестрация пайплайна |
| `worker` | тот же образ что `api`, запускается как воркер очереди (arq или RQ поверх Redis) | Пайплайн задач: скрипт → проверка → озвучка → рендер → метаданные |
| `tts` | Python, FastAPI, плагины моделей (раздел 7) | Синтез речи, менеджер моделей, кеш. Два образа: `tts-cpu` и `tts-gpu` (CUDA) |
| `renderer` | Node 20 + Remotion + headless Chromium | Рендер композиций Remotion в mp4 по JSON-пропсам |
| `postgres` | Postgres 16 | Данные |
| `redis` | Redis 7 | Очередь, pub/sub для прогресса |
| `minio` (опц.) | или просто shared volume `/data` | Хранилище аудио/видео. Достаточно volume, MinIO не обязателен |

- Профили compose: `docker compose --profile cpu up` (по умолчанию) и `--profile gpu up` (tts-gpu с `deploy.resources.reservations.devices` для NVIDIA).
- Shared volumes: `models` (веса TTS/LLM), `data` (аудио, рендеры, ассеты), `pgdata`.
- Прогресс задач в дашборд через SSE или WebSocket (Redis pub/sub → api → web).
- Один `.env.example` со всеми переменными. `make up`, `make down`, `make smoke`, `make logs`.
- Healthchecks у всех сервисов, `web` показывает статус сервисов на главной.

### Почему Remotion
Шаблоны роликов пишутся как React-компоненты: анимации (pop-in, bounce, shake, прогресс-бар, конфетти) делаются легко, и **тот же компонент** используется в дашборде через `@remotion/player` для мгновенного превью без рендера. Композиции получают на вход один JSON (`RenderProps`, раздел 8).
Проверь актуальные условия лицензии Remotion (для индивидуального автора/маленькой команды она бесплатна, но сверь) и запиши вывод в `DECISIONS.md`.
Шаблоны лежат в общем пакете `packages/templates`, который импортируют и `web`, и `renderer` (монорепо на pnpm workspaces).

### Структура репо
```
/apps/web            Next.js дашборд
/apps/renderer       Remotion render server (HTTP: POST /render -> job)
/packages/templates  Remotion композиции + общие TS-типы (генерируются из JSON Schema)
/services/api        FastAPI + worker
/services/tts        TTS сервис с плагинами
/schemas             JSON Schema форматов (источник правды для Python и TS)
/assets              шрифты (OFL), sfx, музыка, наклейки, маскоты, палитры
/content             сиды: серии, банк уроков (YAML)
/legacy              прототип (если есть)
docker-compose.yml, Makefile, .env.example, PLAN.md, DECISIONS.md, README.md
```

## 4. Форматы роликов (шаблоны)

Каждый формат = Remotion-композиция + JSON Schema скрипта + промпт для LLM + правила тайминга. Все форматы 1080x1920, 30 fps, длина 10-35 сек.

1. **`list_mystery`** (классика канала). Заголовок, 5-12 пар, последовательная подсветка, последняя строка `???`/`??`. Варианты левой колонки: число, местоимение, английское слово, артикль, итальянское слово (для пар: контрарии, ед./мн. число, м./ж. род).
2. **`quiz_abc`**. Вопрос («Come si dice "cucchiaio" in inglese?» или наоборот «Как по-итальянски "ложка"?»), 3 варианта A/B/C, кольцо-таймер 3 сек со звуком тиканья. Режим `reveal`: показ ответа с конфетти. Режим `no_reveal`: ответ только в закреплённом комменте. Призыв: «Scrivi A, B o C».
3. **`spot_the_error`** (Trova l'errore). Фраза с одной типичной ошибкой иностранца, таймер, затем (опционально) зачёркивание и правильный вариант ❌→✅. Ошибки должны быть реальными типичными (артикли, предлоги, essere/avere в passato prossimo, согласование), а не опечатками.
4. **`false_friends`** (Falsi amici). «CAMERA ≠ camera», «PARENTI ≠ parents», «MORBIDO ≠ morbid». Последний пример спрятан.
5. **`fill_blank`** (Completa la frase). «Ho fame, vado ___ ristorante» + варианты. Хорош для предлогов и артиклей.
6. **`level_ladder`** (A1→C2). Одно понятие на шести уровнях: «bello → carino → stupendo → mozzafiato...». Хук: «Che livello sei? Scrivilo nei commenti». Самоидентификация уровня даёт массу коротких комментов.
7. **`tongue_twister`** (Scioglilingua). Скороговорка: медленно по словам с подсветкой, затем быстро. Челлендж: «Riesci a dirlo 3 volte?».
8. **`idiom`** (Espressioni). Буквальный смысл vs реальный: «In bocca al lupo» → «Удачи!», затем вопрос «E cosa si risponde?» (ответ «Crepi!» скрыт).
9. **`emoji_vocab`** (Come si dice?). Эмодзи (OpenMoji или Twemoji, проверь лицензии и указывай атрибуцию если нужна) → слово, последний скрыт.
10. **`conjugation_challenge`**. Таблица io/tu/lui/noi/voi/loro для одного глагола и времени, одна или две формы скрыты (не обязательно последняя).
11. **`daily_word`** (серия «Parola del giorno #N»). Слово, произношение, 1 пример, номер эпизода. Серийность возвращает зрителей.

Общие элементы всех шаблонов (настраиваются per-series): палитра, шрифт (Montserrat/Fredoka/Nunito, только OFL), стиль плашек, закладка «сохрани», наклейки, аватар/маскот, прогресс-бар сверху, водяной знак `@ItalianoPerTe`, номер эпизода, второй язык подписей.

**Безопасные зоны Shorts**: ничего важного в нижних ~320 px и правых ~150 px (кнопки YouTube), заголовок не выше 120 px от верха. Сделай в редакторе переключатель «показать оверлей интерфейса YouTube».

## 5. Хуки и механики вовлечения (встроить в шаблоны и генератор)

Ранжирование Shorts сильно зависит от того, досмотрел ли зритель первые секунды или свайпнул, от удержания, повторных просмотров (loop) и комментариев. Поэтому:

**Первые 1-2 секунды**
- Никаких «Ciao ragazzi, oggi...». Кадр 0 уже содержит заголовок и **весь список** (или вопрос): зритель сразу видит «контракт времени» (10 строк = понятно сколько ждать).
- Текст-хук поверх заголовка, генерируется LLM из библиотеки паттернов (раздел ниже), 2-6 слов: «Il 90% sbaglia l'ultima», «Solo i livelli B2 la sanno», «Gli italiani sbagliano questa», «Ultima = impossibile?».
- Голос произносит хук в первые 1.5 сек (YouTube учитывает и произнесённые слова, не только экранный текст).

**Середина**
- Ритм: смена подсветки каждые 0.9-1.4 сек, лёгкий bounce и «pop» звук на каждую строку.
- Прогресс-бар сверху.

**Конец и петля**
- Последний элемент спрятан, `???` пульсирует, голос: «E l'ultima? Scrivila nei commenti!» (варьировать фразы, библиотека из 20+ вариантов, чтобы не было шаблонности).
- Ролик **обрывается без затухания**, последний кадр визуально совпадает с первым (кроме подсветки), чтобы автоповтор выглядел бесшовно. Пока человек пишет коммент, ролик крутится и копит удержание.
- Режим `answer_tomorrow`: ответ не раскрывается в ролике, а публикуется в закреплённом комменте через N часов или в следующем ролике серии кадром «Risposta di ieri: ...». Это возвращает зрителей.

**Типы CTA для комментов** (поле `comment_hook.type`, LLM выбирает подходящий формату, генератор следит за разнообразием в пачке):
- `hidden_answer`: «Scrivi la risposta».
- `abc`: «Scrivi A, B o C» (минимальное трение, один символ).
- `level`: «Che livello sei?».
- `challenge`: «Riesci a dirlo 3 volte veloce?».
- `native_language`: «Come si dice nella tua lingua?» (собирает комменты на разных языках).
- `debate`: реальные спорные/вариативные нормы («la WhatsApp o il WhatsApp?», «i weekend o i weekends?»), только если есть реальная вариативность, никакой выдуманной «правды».
- `streak`: «Commenta "presente" se sei qui dal giorno 1».

**Библиотека паттернов** хранится в БД (`hook_patterns`: текст, тип, язык, формат, счётчик использования, позже метрики), редактируется в дашборде, пополняется LLM. Генератор не повторяет один паттерн чаще, чем раз в X роликов серии.

**A/B-задел**: у каждого ролика можно сгенерировать 2 варианта хука/заголовка (`variant: A|B`). Сейчас просто хранить, на этапе 8 сравнивать по аналитике.

## 6. Контент: серии, идеи, проверка

### Серии (= будущие плейлисты)
Сущность `Series`: название, формат, уровень (A1-C1), тематика, палитра, голос по умолчанию, аватар/маскот, тип хука, режим ответа, нумерация эпизодов, плейлист YouTube (id, позже), расписание (позже), авто-аппрув вкл/выкл.

Сиды при первом запуске (создать с банком примеров по 10-30 уроков на серию, итальянский выверить):
- «Numeri» (list_mystery), «Verbi: presente», «Verbi: passato prossimo», «Articoli», «Plurali», «Contrari», «Vocabolario: cibo / casa / corpo / famiglia / animali / viaggio / al bar / al ristorante», «Falsi amici», «Trova l'errore», «Quiz A/B/C», «Da A1 a C2», «Scioglilingua», «Espressioni italiane», «Parola del giorno».
- Перенести 31 урок из `legacy/lessons/bank.yaml`, если прототип есть.

### Конвейер идей
`Idea` → `Script` → `Verified` → `Approved` → `Rendered` → `Ready` → (`Scheduled` → `Published` позже).

- **Генератор идей**: кнопка «Придумать 20 идей» для серии или «Свободная тема». LLM получает: описание формата, уровень, список уже сделанных тем серии (дедуп), список последних хуков (разнообразие).
- **Генератор скрипта**: превращает идею в JSON по схеме формата. Structured output / JSON mode, валидация Pydantic, до 3 ретраев с ошибкой валидации в промпте.
- **Проверка (обязательно, автоматически)**:
  1. Правила: длины строк (чтобы влезло в плашку при min font size), количество элементов, отсутствие дублей внутри ролика, корректные апострофы (`l'`, `dell'`), наличие обязательных акцентов.
  2. Орфография: LanguageTool (self-hosted контейнер `languagetool`, итальянский) + словарь Hunspell `it_IT` по каждому итальянскому слову.
  3. LLM-верификатор: **отдельный вызов** с ролью строгого преподавателя итальянского, проверяет каждый факт (перевод, форма глагола, артикль, род, «типичность» ошибки в spot_the_error), возвращает `{ok, issues[], fixed_script}`.
  4. Дедуп: нормализованный хеш набора слов + fuzzy сравнение заголовков со всеми прошлыми роликами (и с импортом названий старых шортсов канала, см. этап 8).
  Любая проблема → статус `needs_review` с подсветкой проблемных полей в редакторе.
- **Аппрув**: в серии с `auto_approve=true` всё, что прошло проверки, сразу идёт в рендер. Иначе ручной аппрув в канбане (можно пачкой).

### LLM-провайдеры
Абстракция `LLMProvider` с реализациями: Anthropic API (по умолчанию, модель настраивается в UI), Ollama (локально), OpenAI-совместимый endpoint. Ключи в `.env`, переключение в настройках. Логировать токены и стоимость по каждому вызову, показывать в дашборде.

## 7. Озвучка: менеджер моделей

`tts`-сервис с плагинной архитектурой. Интерфейс плагина:
```
class TTSPlugin:
    id, name, license, languages, requires_gpu, vram_gb, supports_cloning, supports_voice_design
    def is_installed() -> bool
    def install(progress_cb)            # скачивание весов в volume /models
    def list_voices() -> list[Voice]
    def synthesize(text, voice, speed, emotion?, ref_audio?) -> wav (24k/44.1k mono)
```

Кандидаты (агент: **перед реализацией проверь на Hugging Face/GitHub актуальное состояние, поддержку итальянского и лицензию каждой модели**, сведи в таблицу в `DECISIONS.md`):
- **Piper** `it_IT-paola-medium`, `it_IT-riccardo-x_low`: CPU, мгновенно, качество среднее. Базовый fallback, ставится автоматически.
- **Kokoro** (voices `if_sara`, `im_nicola`): маленькая, на CPU приемлемо, звучит живее Piper. Требует espeak-ng в образе.
- **Qwen3-TTS** (0.6B / 1.7B, есть итальянский, zero-shot клонирование и «voice design» по текстовому описанию): кандидат №1 для GPU. Voice design позволит создать фирменный голос канала по описанию («warm young Italian female teacher, clear diction, slightly slow»).
- **Chatterbox Multilingual** (Resemble AI, MIT): клонирование по короткому образцу, параметр эмоциональности. Кандидат для GPU.
- **Voxtral TTS** (Mistral, итальянский в списке языков, около 16 GB VRAM): проверить лицензию весов.
- **MOSS-TTS-Nano / PocketTTS**: лёгкие CPU-модели с клонированием, проверить качество итальянского и лицензию.
- **XTTS-v2**: только если лицензия разрешает коммерческое использование. У Coqui XTTS-v2 лицензия некоммерческая, канал монетизируется, поэтому в UI пометить красным «non-commercial» и по умолчанию не предлагать.

Страница «Голоса» в дашборде:
- карточки моделей: статус (не установлена / качается N% / готова), требования (CPU/GPU, VRAM), лицензия с бейджем коммерческого использования, кнопки «Скачать», «Удалить», «Тест»;
- автоопределение железа (есть ли CUDA, сколько VRAM), неподходящие модели серые с объяснением;
- тестовая фраза + прослушка, **A/B сравнение** двух голосов на одной фразе, слепое голосование для выбора;
- создание голоса: из встроенных, voice design по описанию, клон по референсу (загрузка wav 10-30 сек + чекбокс «у меня есть согласие владельца голоса»). Рекомендация в UI: лучший вариант для монетизации и уникальности канала: клон собственного голоса владельца или голос, созданный через voice design;
- голос по умолчанию на серию, скорость (для учеников 0.85-0.95), паузы.

Тайминг: синтезировать **каждую строку отдельно**, обрезать тишину по краям, собирать таймлайн с паузами из настроек; это даёт точную синхронизацию подсветки без forced alignment. Для форматов с целыми фразами (scioglilingua, idiom) нужен пословный тайминг: добавить в `tts` опциональный aligner (faster-whisper word timestamps или ctc-forced-aligner, выбрать и обосновать).
Кеш: ключ `sha1(model|voice|speed|text)`, переиспользовать между роликами. Нормализация громкости (EBU R128, -14 LUFS) на этапе финального микса.

## 8. Рендер

`RenderProps` (генерируется из JSON Schema, общий для Python и TS):
```
{
  format, series_id, episode_no,
  canvas: {w:1080, h:1920, fps:30},
  theme: {bg, palette, font, badge_styles, sticker_set, watermark, show_progress_bar},
  hook_text, title, body: <формат-специфичный объект>,
  timeline: [{t_start, t_end, action: "show_title"|"highlight"|"reveal"|"countdown"|..., target}],
  audio: {voice_url, music_url?, music_volume, sfx: [{t, name}]},
  avatar: {mode: "none"|"loop"|"mascot"|"lipsync", src?, position, height},
  loop_seamless: true
}
```
- Remotion-композиция на каждый формат, общие компоненты (Pill, Badge, TitleChip, ProgressBar, Bookmark, Sticker, Countdown, Confetti, Avatar).
- Аудио: голос + опциональная музыка из `assets/music` (только то, что положил владелец или явный CC0/royalty-free, с полем источника/лицензии) + SFX (pop, tick, ding, whoosh: сгенерировать процедурно или CC0, хранить с атрибуцией).
- Вариативность, чтобы ролики не выглядели клонами: случайная палитра из набора серии, разные раскладки (столбец по центру/слева, плашки скруглённые/квадратные), разные наклейки, разные позиции закладки, разные фразы хуков. Сид вариативности сохраняется, рендер воспроизводим.
- **Аватар/ведущая**, режимы:
  - `none`;
  - `loop`: зацикленное видео ведущей (green screen → chromakey, или webm/mov с альфой), губы не синхронизированы;
  - `mascot`: оригинальный 2D-маскот канала (например кусочек пиццы или Колизей в стиле аватарки канала), 3-5 спрайтов рта, переключаемых по RMS-огибающей голоса, моргание по таймеру, подпрыгивание на подсветке. Дёшево, без GPU, узнаваемо. Сгенерировать стартовый маскот как SVG-спрайты, дать возможность заменить своими PNG;
  - `lipsync` (этап 6, GPU): прогон лупа ведущей через open-source lip-sync модель (LatentSync / MuseTalk или актуальный аналог, проверить лицензию) по готовому аудио.
- Выход: `video.mp4` (H.264, yuv420p, CRF ~18, AAC 192k, faststart), `cover.png` (кадр со всем списком), `meta.json`, `script.json`.
- Время рендера одного ролика на CPU цель: < 90 сек. Параллельный рендер N воркеров (настройка).

### Метаданные (генерирует LLM, проверяет правило-движок)
- `title` (≤ 70 символов, хук + тема + 1-2 эмодзи, без кликбейта, не обещать того, чего нет в ролике), 2 варианта A/B;
- `description` (2-3 строки + хештеги, ссылка на плейлист серии);
- `tags`, `hashtags` (3-5);
- `pinned_comment` (ответ или вопрос-продолжение), `answer_reveal_at`;
- `playlist` (из серии), `episode_no`.
Кнопки «скопировать» для каждого поля в библиотеке.

## 9. Дашборд (страницы)

1. **Главная**: большая кнопка «🚀 Сгенерировать» (выбор: серия или «микс серий», количество 1-50, авто-аппрув да/нет), статус сервисов, очередь с прогрессом по этапам, последние готовые ролики, расход LLM за день/месяц.

3. **Серии**: CRUD, настройки серии (раздел 6), статистика (сколько сделано/в банке), кнопка «Наполнить банк» (LLM придумывает N уроков).

5. **Библиотека**: сетка готовых роликов с превью, фильтры, скачать mp4 / zip пачки, копирование метаданных, отметка «опубликовано вручную» (+ ссылка), статус ответа-коммента.
6. **Голоса**: раздел 7.
7. **Хуки**: библиотека паттернов, добавление, генерация новых, частота использования.

## 10. Политика YouTube и качество (важно для монетизации)

YouTube Partner Program не монетизирует «массово производимый / повторяющийся» контент (политика inauthentic content, раньше называлась repetitious content). Шаблонная автогенерация в лоб под неё попадает. Поэтому в системе обязательно:
- реальная обучающая ценность каждого ролика (проверка корректности, понятная структура);
- разнообразие форматов, раскладок, голосовых фраз и хуков внутри пачки (генератор следит, в дашборде показывать «индекс похожести» пачки);
- рекомендация в UI использовать фирменный голос (клон владельца или voice design), а не стоковый;
- ручной аппрув по умолчанию включён для новых серий;
- лимит «не больше N роликов в день на публикацию» в календаре (настройка, по умолчанию 2-3).
Агент: проверь актуальный текст политики YouTube на момент реализации и вынеси краткую памятку в `README.md`.

## 12. Этапы

**Этап 1. Скелет и один формат end-to-end (CPU)**
Монорепо, compose (cpu), Postgres+Redis, FastAPI с миграциями, Next.js с главной и библиотекой, `tts` с Piper, Remotion `list_mystery`, банк уроков из сидов. Кнопка «Сгенерировать 3» → 3 mp4 в библиотеке.
Готово, когда: `docker compose up` на чистой машине, кнопка работает, `make smoke` рендерит 3 ролика, тесты зелёные.

**Этап 2. Серии, канбан, редактор с живым превью**
Серии, идеи, статусы, редактор по JSON Schema, Remotion Player, SSE-прогресс.

**Этап 3. LLM: идеи, скрипты, проверка**
Провайдеры, генерация идей/скриптов/метаданных, LanguageTool + Hunspell + LLM-верификатор, дедуп, `needs_review`.

**Этап 4. Все форматы и хуки**
Остальные 10 шаблонов, библиотека хуков, SFX, музыка, вариативность, бесшовная петля, `answer_tomorrow`.

**Этап 5. Менеджер голосов**
Плагины Kokoro, Qwen3-TTS, Chatterbox (+ остальные по результатам проверки), профиль `gpu`, скачивание с прогрессом, A/B, voice design, клонирование, aligner.

**Этап 6. Ведущая**
`loop` (chromakey/alpha), `mascot` с липсинком по амплитуде, опционально `lipsync` на GPU.

**Этап 7. Автозагрузка** (по команде владельца)
Раздел 11 + календарь.

**Этап 8. Обратная связь** (по команде владельца)
Импорт названий существующих шортсов канала для дедупа, YouTube Analytics API (удержание, просмотры, комменты по роликам), дашборд «что заходит» по форматам/хукам/сериям, подача лучших примеров в промпт генератора, сравнение A/B вариантов.

## 14. Критерии приёмки всего проекта

1. Чистая Windows-машина с Docker Desktop: `git clone` → `cp .env.example .env` → `docker compose up` → `http://localhost:3000` открывается без ручных шагов.
2. Без GPU и без ключей LLM: кнопка «Сгенерировать 10» из банка серии выдаёт 10 разных корректных роликов.
3. С ключом LLM: «Придумать 20 идей» → аппрув → рендер, ни одной орфографической ошибки в итоговых роликах на выборке из 20 (проверка LanguageTool в отчёте).
4. В пачке из 10 роликов одной серии нет двух одинаковых палитр подряд и одинаковых фраз-хуков.
5. Превью в редакторе совпадает с рендером (golden-тест).
6. Модель TTS скачивается и включается из UI без терминала.
